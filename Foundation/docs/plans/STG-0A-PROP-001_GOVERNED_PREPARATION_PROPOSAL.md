# STG-0A-PROP-001 — Stage 0A Governed Preparation Proposal

**Identifier:** STG-0A-PROP-001  
**Version:** 1.0  
**Status:** Approved  
**Proposal Date:** 2026-07-25  
**Owner:** Falcon Foundation Governance  
**Governing Authority:** Falcon Vision; Falcon Constitution; GOV-001 v1.2; ADR-I008; AMD-003; ROADMAP-001 v2.8; FCL-001  
**Prepared Under:** Project Owner authorization to prepare a proposal only  
**Approval Record:** GOV-047  
**Implementation Authority:** Not Granted  
**Execution Authority:** Not Granted  
**Activation Authority:** Not Granted  
**Production Authority:** Not Granted  
**Cloud Deployment Authority:** Not Granted  
**Financial Authority:** Not Granted

## 1. Purpose

This proposal defines the next eligible Falcon phase:

```text
Stage 0A — Governed Preparation
```

Stage 0A exists to prepare a bounded, non-financial, non-operational Windows-based preparation environment so Falcon can later construct and verify enabling Foundation candidates under separate authority.

This document is a proposal only.

It does not authorize preparation, installation, download, execution, verification, Activation, implementation, production, cloud deployment, financial connectivity, or financial activity.

## 2. Stage Identity

Stage 0A is a preparation phase.

It is not:

- Falcon implementation;
- Falcon runtime;
- a trading system;
- a test of financial behavior;
- an operational environment;
- a production environment;
- a cloud deployment;
- a Provider Activation;
- a Pipeline Activation;
- or a financial readiness phase.

Stage 0A prepares the ground.

It does not build Falcon.

## 3. Strategic Direction

Falcon’s immediate practical path is:

```text
Local Windows preparation
→ short local Foundation verification window
→ later governed Oracle Cloud direction
```

The local Windows path is temporary and transitional.

Windows is the first preparation platform. It is not Falcon’s identity.

Oracle Cloud Infrastructure is the intended first future cloud direction. It is not admitted, provisioned, activated, or authorized by this proposal.

Stage 0A SHALL remain local-first and cloud-ready.

## 4. Prime Objective Alignment

Stage 0A exists only to preserve Falcon’s ordered Prime Objective:

```text
Protect Capital
→ Manage Capital
→ Grow Capital
```

Because Stage 0A is pre-operational, its direct contribution is protection:

- prevent uncontrolled setup;
- prevent hidden authority expansion;
- prevent accidental financial connection;
- prevent secret leakage;
- prevent dependency lock-in;
- prevent undocumented environment drift;
- preserve evidence;
- and prepare a safe path toward later verified implementation.

## 5. Scope

Stage 0A may propose preparation of:

- local Windows preparation directory structure;
- repository hygiene;
- exact tool inventory;
- exact dependency-acquisition policy;
- exact non-financial data policy;
- exact secret absence policy;
- exact evidence location;
- exact environment manifest format;
- exact stop conditions;
- exact cleanup conditions;
- and exact readiness criteria for later Stage 0B proposal.

Stage 0A may not propose any action that exposes capital, credentials, accounts, orders, positions, portfolios, market connectivity, broker connectivity, customer data, production secrets, or cloud resources.

## 6. Required Authority Instrument

Stage 0A SHALL NOT begin until a separate Authority Instrument is approved.

That Authority Instrument SHALL define:

- authority identifier;
- approving authority;
- exact scope;
- exact start condition;
- exact expiration condition;
- exact permitted tools;
- exact permitted directories;
- exact network permissions, if any;
- exact evidence obligations;
- exact financial-isolation obligations;
- exact stop conditions;
- exact cleanup obligations;
- accountable owner;
- challenge path;
- revocation rule;
- and explicit non-authorities.

This proposal does not create that Authority Instrument.

## 7. Bootstrap Execution Context

Stage 0A SHALL require a Bootstrap Execution Context before any preparation action occurs.

The Bootstrap Execution Context SHALL identify:

- preparation environment;
- execution identity;
- permitted filesystem boundaries;
- permitted command classes;
- permitted network destinations, if any;
- allowed input materials;
- prohibited input materials;
- evidence capture location;
- time source;
- identity source;
- tool source;
- cleanup rules;
- stop rules;
- and maximum duration.

Any action outside the Bootstrap Execution Context SHALL stop the preparation activity.

## 8. Windows Local Preparation Rule

The first Stage 0A target platform is Windows.

Windows preparation SHALL:

- remain local and non-operational;
- avoid user-specific assumptions where possible;
- avoid hard-coded personal paths in Falcon meaning;
- keep environment facts in evidence, not in governing policy;
- preserve portability to future Linux and Oracle Cloud phases;
- avoid Windows-only semantics crossing Falcon Contracts;
- avoid tool choices that prevent cloud migration;
- and remain valid only for its declared Windows scope.

Local operation for one or two days after later implementation may be anticipated, but not authorized here.

## 9. Oracle Cloud Readiness Boundary

Stage 0A may document cloud-readiness considerations only.

It SHALL NOT:

- create an Oracle Cloud tenancy;
- create a compartment;
- select or activate OCI services;
- create cloud identities;
- store cloud credentials;
- create cloud resources;
- install cloud SDKs for operational use;
- deploy Falcon;
- or test cloud runtime behavior.

Any future OCI work requires separate cloud authority, cloud environment profile, evidence obligations, and Project Owner approval.

## 10. Financial Isolation

Stage 0A SHALL be financially sterile.

It SHALL NOT include:

- broker accounts;
- exchange accounts;
- bank accounts;
- custodians;
- market data subscriptions;
- trading credentials;
- API keys for financial services;
- real orders;
- real positions;
- real portfolios;
- real capital;
- customer financial data;
- or production financial datasets.

Any discovery of financial material SHALL stop the activity and trigger evidence preservation and review.

## 11. Secret and Credential Policy

Stage 0A SHALL assume secrets are prohibited unless a specific Authority Instrument permits a synthetic or test-only secret class.

Stage 0A SHALL NOT introduce:

- production secrets;
- cloud credentials;
- broker credentials;
- private keys;
- reusable security material;
- personal access tokens in source;
- credentials in configuration;
- credentials in logs;
- or credentials in evidence.

Evidence SHALL prove absence of prohibited secret classes before any later stage is proposed.

## 12. Tool and Dependency Policy

Stage 0A may identify tools.

It SHALL NOT install, download, execute, activate, or trust tools unless separately authorized.

Any future tool use SHALL follow:

- BCL-first policy where implementation later applies;
- Adapter isolation for external dependencies;
- no vendor lock-in;
- exact source;
- exact version;
- exact digest where applicable;
- license awareness;
- vulnerability awareness;
- reproducibility;
- and evidence capture.

## 13. Evidence Obligations

Stage 0A preparation, once separately authorized, SHALL preserve evidence for:

- authorized scope;
- execution identity;
- environment identity;
- filesystem boundaries;
- tool inventory;
- dependency sources;
- network use;
- secret absence;
- financial isolation;
- commands or actions performed;
- produced files;
- changed files;
- failures;
- stop decisions;
- cleanup;
- and final readiness finding.

Evidence SHALL be attributable, immutable after recording, and sufficient for later independent review.

## 14. Self-Awareness and Self-Maintenance Boundary

Stage 0A preserves Falcon’s Self-Aware direction.

Future Self-Awareness may observe, diagnose, recommend, and propose maintenance or evolution.

It may not:

- create its own authority;
- expand jurisdiction;
- approve its own proposal;
- activate itself;
- bypass Guardian;
- conceal uncertainty;
- weaken evidence;
- alter Vision or Constitution;
- introduce financial authority;
- or convert preparation into implementation.

Self-Maintenance and Evolution remain governed capabilities, not uncontrolled autonomy.

## 15. Stop Conditions

Stage 0A SHALL stop if:

- scope becomes unclear;
- authority is missing, expired, revoked, or challenged;
- a prohibited tool is required;
- a prohibited network destination is required;
- financial material is discovered;
- production secret material is discovered;
- evidence cannot be preserved;
- environment boundaries cannot be proven;
- a required action would imply implementation;
- a required action would imply Activation;
- a required action would imply cloud deployment;
- or a required action would violate Vision, Constitution, Guardian policy, or capital protection.

Failure does not expand authority.

## 16. Exit Criteria

Stage 0A may be considered complete only when separately authorized preparation produces an accepted record showing:

- exact preparation actions completed;
- no prohibited financial material;
- no prohibited secrets;
- known tools and versions;
- known environment boundaries;
- known unresolved risks;
- complete required evidence;
- cleanup completed or intentionally preserved;
- and a clear recommendation for whether Stage 0B may be proposed.

Completion of Stage 0A SHALL NOT authorize Stage 0B.

## 17. Proposed Next Decision

If this proposal is accepted, the next document SHALL be:

```text
STG-0A-AUTH-001 — Stage 0A Governed Preparation Authority Instrument
```

That document would request permission to perform exact preparation actions.

This proposal does not request or grant that permission.
