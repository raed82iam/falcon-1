**Financial Authority:** Not Granted

## 1. Purpose

This instrument defines the bounded authority governing Stage 0B.

It is effective only within the complete package approved by GOV-051.

## 2. Authority Requested

This instrument authorizes only:

- creation of the explicitly enumerated enabling candidates in STG-0B-SCP-001;
- use of the exact admitted local tools in STG-0B-BLD-001;
- operation inside the exact Bootstrap Execution Context in STG-0B-BEC-001;
- use of the candidate-verification environment defined by STG-0B-ENV-001;
- synthetic-only material governed by STG-0B-SYN-001;
- execution of the verification scope in STG-0B-VER-001;
- preservation of evidence required by STG-0B-EVD-001;
- financial-isolation checks in STG-0B-FIN-001;
- and cleanup and closure under STG-0B-EXIT-001.

## 3. Exact Authority Boundary

The authority would apply only to:

- local Windows;
- the Falcon repository;
- non-operational enabling-candidate source and verification fixtures;
- local build and verification processes;
- synthetic inputs;
- and documentation and evidence generated by the authorized case.

Every output shall remain classified `CANDIDATE`.

## 4. Prohibited Authority

This instrument shall not authorize:

- general Falcon behavior;
- operational Core components;
- Provider or Profile Activation;
- Stage 0C;
- Stage 1;
- production;
- Oracle Cloud or any cloud resource;
- financial connectivity or data;
- real credentials or secrets;
- market, broker, bank, exchange, or custodian integration;
- autonomous Self-Maintenance or Evolution;
- candidate self-approval;
- or authority expansion.

## 5. Accountable Roles

| Responsibility | Accountable Authority |
|---|---|
| Scope approval | Project Owner |
| Construction execution | Authorized Stage 0B executor |
| Evidence production | Authorized tools and executor |
| Evaluation | Authority independent from the candidate under evaluation |
| Evidence completeness | Authority not solely responsible for producing or aggregating the evidence |
| Activation | Not available in Stage 0B |
| Revocation | Project Owner |

## 6. Start Conditions

Stage 0B may start only after:

- all ten decision-package documents are Approved;
- the Project Owner explicitly grants Stage 0B start authority;
- repository and evidence baselines are recorded;
- tool identities and integrity are recorded;
- the Bootstrap Execution Context is fixed;
- the Evidence Requirement Set is fixed;
- and all entry checks report `SATISFIED`.

## 7. Stop and Revocation

Work shall stop immediately upon:

- authority ambiguity, expiry, revocation, challenge, or scope excess;
- evidence failure;
- unapproved dependency need;
- candidate/active-state ambiguity;
- secret-custody failure;
- financial or cloud contact;
- or any violation named by the companion documents.

Revocation requires no candidate consent.

## 8. Duration

If approved, the authority shall expire at the earliest of:

- Stage 0B completion or stop report;
- Project Owner revocation;
- material scope change;
- evidence or isolation failure;
- 14 calendar days after approval;
- or the moment any companion document is superseded.

Expiration shall not authorize continuation, retry, cleanup beyond the approved cleanup rule, or later-stage work.

## 9. Approval Requirement

This candidate shall not become effective through implication, commit, publication, successful build, or successful verification.

Only an explicit Project Owner approval of the complete Stage 0B decision package may grant the bounded authority described here.
