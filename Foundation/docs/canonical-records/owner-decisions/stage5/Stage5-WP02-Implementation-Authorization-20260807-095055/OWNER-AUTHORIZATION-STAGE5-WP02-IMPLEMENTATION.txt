OWNER AUTHORIZATION

The Owner authorizes implementation of:

Stage 5 WP-02 - Schema Registry and Compatibility

WP-02 PURPOSE

WP-02 shall establish the application-neutral governed schema registry
and deterministic compatibility model required by later Stage 5 communication work.

WP-02 AUTHORIZED SCOPE

WP-02 may implement only the approved contracts, registry structures,
validators, compatibility evaluators, persistence abstractions where required,
documentation, and verification coverage necessary for:

1. Canonical schema registration using the WP-01 SchemaIdentity.
2. Explicit schema version registration.
3. One declared owner or governing owner reference per registered schema.
4. Schema attribution and provenance required to identify the accepted definition.
5. Deterministic schema lookup by canonical schema identity and version.
6. Explicit compatibility classifications:
   exact, backward, forward, incompatible.
7. Deterministic compatibility evaluation between declared schema versions.
8. Fail-closed rejection of unknown or undeclared schema identities and versions
   when no explicit compatibility rule permits them.
9. Prevention of silent schema-version reinterpretation.
10. Separation of envelope compatibility from Application payload meaning.
11. Prevention of schema registration or technical discoverability from
    granting execution, business, or Owner authority.
12. Duplicate schema registration rejection.
13. Conflicting schema-owner or version-definition rejection.
14. Deterministic registry state and replay behavior.
15. Version lineage and compatibility evidence sufficient for later
    message-admission work without implementing that admission work.
16. Zero-Application Foundation compatibility.
17. At least two independent Application-neutral schema fixtures.
18. Positive compatibility fixtures.
19. Negative and mutation fixtures.
20. Architecture tests.
21. Security tests.
22. Deterministic verifier rerun.
23. WP-02 documentation and requirement-to-verifier traceability.

MANDATORY WP-02 COMPATIBILITY PRINCIPLES

Every schema shall be versioned and attributable.
Every schema shall have one declared owner.
Compatibility shall be explicit, never inferred from transport success.
Compatibility values are exact, backward, forward, or incompatible.
Undeclared schema versions shall fail closed unless an explicit governing
compatibility rule permits the relationship.
Schema changes shall not silently alter payload meaning.
Envelope compatibility and Application payload meaning remain separate.
Foundation shall not interpret Application business payload semantics.

MANDATORY VERIFICATION BEFORE OWNER ACCEPTANCE

Evidence shall show:

- clean Release build;
- zero warnings and zero errors;
- architecture tests pass;
- security tests pass;
- all previously accepted Stage 2 through Stage 4 verifiers remain passing;
- Baseline Integrity verifier remains passing;
- accepted WP-01 verifier remains passing;
- WP-02 verifier passes positive, negative, mutation, and ambiguity cases;
- exact, backward, forward, and incompatible compatibility are verified;
- unknown schema and undeclared-version behavior fails closed;
- duplicate and conflicting registration fails closed;
- deterministic rerun produces equivalent accepted results;
- zero-Application and two-independent-Application fixtures pass;
- documentation and traceability are complete;
- independent architecture review is completed;
- independent red-team review is completed;
- independent completeness review is completed.

MANDATORY BOUNDARIES

WP-02 shall remain:

- application-neutral;
- domain-independent;
- free of FSATS, trading, market, broker, accounting, web,
  communication-application, or other business semantics;
- compatible with zero installed Applications;
- compatible with multiple independent Applications;
- compatible with accepted Stage 0 through Stage 4 behavior;
- compatible with accepted and closed Stage 5 WP-01;
- fail-closed;
- deterministic;
- modular, versioned, replaceable, and independently testable.
