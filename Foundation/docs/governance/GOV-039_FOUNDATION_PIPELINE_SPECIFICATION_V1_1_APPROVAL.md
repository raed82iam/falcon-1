## 3. Effect

This Approval:

- establishes distinct `BOOTSTRAP` and `GOVERNED` Pipeline modes;
- admits the three bootstrap Build Intents and their Gate Profile definitions as approved but not active;
- activates Authority Instrument, CON-020 context, external identity and time, evidence, reconstruction, and exact Activation rules;
- establishes Windows as the ordered first governed execution platform;
- preserves provider-neutral execution and future separately admitted Oracle Cloud support;
- activates prohibitions against self-certification, self-promotion, fallback, and autonomous authority expansion;
- preserves PIPE-001 v1.0 decisions not expressly amended; and
- authorizes dependent-document and traceability updates.

## 4. Pipeline and Gate State

Approval of the Specification establishes governed Pipeline meaning.

It does not activate:

- `FALCON-GATE-BOOTSTRAP-PREP-1`;
- `FALCON-GATE-BOOTSTRAP-PROVIDER-1`;
- `FALCON-GATE-BOOTSTRAP-RECON-1`;
- any v1.0 Gate Profile;
- a Pipeline Definition, runner, execution, Verification Session, or Evidence Set;
- a Windows, Linux, or Oracle Cloud environment; or
- any enabling Provider.

Each executable subject requires separate authority, evidence, and an exact Activation Decision.

## 5. Boundaries

This Approval does not:

- issue an Authority Instrument or Bootstrap Execution Context;
- authorize preparation, verification, build, promotion, deployment, migration, or recovery execution;
- produce or promote an artifact;
- establish Pipeline, Gate, Provider, environment, evidence, or artifact validity;
- authorize implementation;
- authorize production;
- authorize financial connectivity; or
- authorize financial activity.
