# Plug-and-Play Application Lifecycle

**Status:** Proposed

```text
Package
  → Identity and Manifest validation
  → Authority, Contract, dependency, and security validation
  → Sandbox
  → Digital City when required
  → FSA Foundation-conformance assessment
  → Admission decision
  → Service/Guardian registration
  → controlled activation
  → operation / suspension / isolation
  → upgrade candidate
  → compatibility and independent verification
  → canary when approved
  → adoption or rollback
  → removal and reconciliation
  → archived evidence
```

Every transition requires explicit authority and evidence. Installation is not activation. Compatibility is not admission. FSA conformance is not business correctness. Removal SHALL preserve Foundation completeness and other Applications.

Application state, Suite state, Guardian state, Platform state, and domain-protection state remain independent.
