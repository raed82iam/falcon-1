# Guardian Authority and Knowledge Matrix

**Status:** Approved Supporting Architecture  
**Approval Record:** GOV-060

## 1. Authority Ownership

| Concern | Authoritative owner | FSA role | FFG role | Application Guardian role |
|---|---|---|---|---|
| Foundation technical condition | FSA for awareness assessment | owns | consumes evidence | receives only authorized summary |
| Foundation protective restriction | FFG | requests or supplies evidence | owns | may submit abstract request |
| Platform Safe Mode | FFG | verifies readiness | owns mode decision | no authority |
| Authority validity | AUT-001 | supplies condition evidence | requests restriction | uses only delegated authority |
| Technical execution | competent Foundation mechanism | verifies result | directs within mandate | no direct ownership |
| Foundation Self-Repair | FSA plus execution owner under playbook | diagnoses and verifies | protects during repair | no authority |
| Foundation Self-Evolution | governed candidate lifecycle | may create isolated candidate | may hold unsafe candidate isolated | no authority |
| Capital and financial protection | future Application/domain authority | no business interpretation | no business interpretation | may own if explicitly chartered |
| Restriction release | authority defined by consequence class, with FFG condition decision | verifies repair where applicable | evaluates FFG release conditions | cannot release FFG restriction |

## 2. Knowledge Boundary

| Information | FFG access |
|---|---|
| Application/component/runtime identity | Allowed |
| technical dependency and criticality | Allowed through governed metadata |
| resource, communication, health, integrity, and authority state | Allowed |
| approved degraded mode and recovery order | Allowed |
| technical envelope and validation outcome | Allowed |
| business payload meaning | Prohibited |
| customers, balances, exposure, capital, orders, positions, portfolios | Prohibited |
| strategy, prediction, commercial importance | Prohibited |

## 3. Mutual Supervision

| Condition | Permitted response | Prohibited shortcut |
|---|---|---|
| FFG unhealthy | FSA verifies and restores Approved state under playbook | FSA changes mandate or releases restrictions |
| FSA unsafe | FFG restricts under explicit mandate and independent evidence | FFG modifies FSA |
| FFG challenged | independent verifier and competent release authority review | FFG conclusively validates itself |
| FSA repair challenged | independent evidence and competent authority review | FSA approves its own new candidate |

## 4. Governing Invariant

Awareness, protection, execution, verification, acceptance, and release remain distinct acts even when one runtime participates in more than one workflow.
