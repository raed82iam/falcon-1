# FSATS V1.4 PROPOSED — V1.3 Correction Preservation Matrix

## Purpose

This matrix prevents V1.4 from accidentally reviving structures that were already removed or hardened inside the final V1.3 package.

The full owner-provided V1.3 package has been inspected. **Final V1.3 is the FSATS Application-architecture migration baseline for V1.4.** It is not Foundation authority, and current Foundation authority wins where an actual Foundation/Application integration conflict exists. V1.4 does not otherwise reopen mature V1.3 trading design merely because the Foundation has evolved.

## Classification

- `PRESERVE` — keep final V1.3 architecture/safety/performance intent.
- `ALIGN` — preserve the intent but rebind ownership/contracts/resources/permissions/lifecycle to current Foundation.
- `SUPERSEDE` — do not carry an already removed/replaced structure forward.
- `OWNER_DECISION` — use only when a real unresolved delta requires explicit Owner choice.

## Guardian current-Owner strengthening

V1.4 strengthens but does not replace the final V1.3 trading-scoped Guardian model:

1. contain incidents at the smallest safe scope;
2. where one user/account is affected, isolate/remediate that scope when safely possible;
3. broad restrictions require evidence of broad trading-domain risk;
4. Trading Guardian may request additional Foundation resources during broad danger;
5. Trading Guardian never self-allocates Foundation resources and never becomes Foundation Guardian.

## Execution-authority separation

Foundation lifecycle and trading execution authority remain orthogonal:

- Foundation `ACTIVE` does not imply Paper/Tiny Live/Live authority;
- Simulation, Shadow, Paper, Tiny Live and Live require separate trading/governance gates;
- this V1.4 design grants none of those runtime authorities.

## Residual V1.3 risks that remain evidence-dependent

V1.4 SHALL NOT claim architecture can eliminate undocumented/changing provider behavior, implementation bugs/races/database failure, overfitting/regime change, impossible fills during halts/vanished liquidity, legal/regulatory/entitlement changes, insufficient empirical strategy evidence, or simulator-to-reality gap.

These require later implementation, simulation, Shadow, Paper, Tiny Live evidence, reconciliation, Guardian controls and stage gates.
