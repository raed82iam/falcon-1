# Shared Falcon Web - معاينة الحملة قبل النشر

**Status:** `DRAFT / DISCUSSION ONLY`

هذا الملف يكمل قرارات تخطيط الحملات والعروض المسجلة في ملف `11 - تذكيرات انتهاء VIP والاحتفاظ.md`، ويختص بشكل المعاينة النهائية قبل النشر من منظور UX/Product فقط. لا يمنح implementation/runtime/publishing authority.

---

## 1. المعاينة البصرية النهائية

اعتمد الـOwner أن شاشة التأكيد النهائية قبل نشر العرض أو الحملة لا تكتفي بعرض النص الخام أو البيانات الوصفية فقط، بل تعرض **Preview بصريًا قريبًا من الشكل الفعلي الذي سيراه المستخدم داخل Falcon**.

المعاينة يجب أن تساعد الـOwner على مراجعة الحملة بصريًا قبل التأكيد النهائي، وتشمل ضمن سياق التأكيد النهائي المعتمد مسبقًا:

- اسم العرض/الحملة؛
- العدد النهائي للمستخدمين المستهدفين بعد الإضافات والاستبعادات اليدوية؛
- محتوى العرض الحالي؛
- الشكل البصري التقريبي لظهور العرض للمستخدم داخل Falcon؛
- خيار الرجوع للتعديل؛
- ثم تأكيد نشر صريح.

```text
OWNER REQUESTS PUBLISH
        ↓
FINAL REVIEW
  - CAMPAIGN NAME
  - FINAL AUDIENCE COUNT
  - CURRENT CAMPAIGN CONTENT
  - VISUAL USER-FACING PREVIEW
        ↓
OWNER REVIEWS
        ↓
OWNER CONFIRMS PUBLISH
        ↓
PUBLISH REQUEST MAY PROCEED
```

### 1.1 المعاينة يجب أن تعكس النسخة الحالية

إذا عاد الـOwner وعدّل المحتوى أو الجمهور أو أي عنصر يؤثر على شكل العرض، يجب أن تتحدث المعاينة قبل السماح بالتأكيد النهائي.

```text
EDIT AFTER PREVIEW
!=
OLD PREVIEW STILL VALID

CURRENT CAMPAIGN STATE
→
CURRENT VISUAL PREVIEW
```

### 1.2 نطاق الجهاز الحالي للمعاينة

اعتمد الـOwner أن النطاق الحالي للـShared Falcon Web هو **واجهة Web للكمبيوتر فقط** في هذه المرحلة، ولذلك لا توجد حاجة الآن إلى تبديل المعاينة بين Desktop وMobile أو إنشاء Mobile Preview مستقل.

المعاينة النهائية للحملة في التخطيط الحالي تمثل فقط الشكل المتوقع داخل واجهة Falcon Web على الكمبيوتر.

```text
CURRENT WEB UX SCOPE = DESKTOP WEB
CURRENT CAMPAIGN PREVIEW = DESKTOP WEB PREVIEW ONLY
MOBILE PREVIEW = NOT CURRENTLY REQUIRED
NO MOBILE UX IS INFERRED FROM DESKTOP PREVIEW
```

إذا تم اعتماد واجهة Mobile أو نطاق جهاز آخر مستقبلًا، يعاد بحث معاينته ضمن تصميمه الخاص بدل افتراض أن معاينة الكمبيوتر تكفي له.

### 1.3 شكل ظهور الحملة للمستخدم ومسارات الرجوع إليها

اعتمد الـOwner أن العرض/الحملة داخل Falcon يظهر للمستخدم أول مرة كـ **Popup** واضح داخل واجهة Falcon Web للكمبيوتر.

إغلاق الـPopup لا يعني أن العرض يختفي نهائيًا. يجب أن يبقى المستخدم قادرًا على الرجوع إلى نفس العرض لاحقًا من **خانة/مركز التنبيهات داخل Falcon** طوال الفترة التي تكون فيها الحملة أو الرسالة ما زالت صالحة للعرض وفق السياسة النهائية.

كما يمكن أن يصل نفس العرض عبر **البريد الإلكتروني** كقناة إضافية عندما يكون البريد الإلكتروني لهذه الفئة من الرسائل مسموحًا ومفعّلًا وفق تفضيلات وموافقات المستخدم الحالية.

```text
FIRST IN-FALCON PRESENTATION = POPUP
CLOSE POPUP != DELETE CAMPAIGN MESSAGE
CLOSE POPUP != LOSE ACCESS
CAMPAIGN MESSAGE -> FALCON NOTIFICATION CENTER
USER MAY REOPEN FROM NOTIFICATIONS
EMAIL = ADDITIONAL CHANNEL WHEN USER PREFERENCES / CONSENT ALLOW
ACCOUNT EMAIL EXISTS != EMAIL MARKETING CONSENT
```

الـPopup هو طريقة العرض الأولية داخل Falcon، بينما مركز التنبيهات هو مسار الرجوع الداخلي بعد الإغلاق. البريد ليس بديلًا إلزاميًا عن مركز التنبيهات، ولا يتم افتراض إرساله لمجرد وجود بريد مسجل في الحساب.

### 1.4 حالة Unread عند إغلاق الـPopup بدون تفاعل

اعتمد الـOwner أن **إغلاق الـPopup وحده لا يُعتبر قراءة للحملة**.

إذا أغلق المستخدم الـPopup بدون أن يفتح الحملة من مركز التنبيهات أو يدخل في تفاعل يعتبره التصميم النهائي قراءة فعلية، تبقى الحملة ظاهرة في مركز التنبيهات بحالة **Unread**.

```text
POPUP SHOWN != READ
POPUP CLOSED != READ
POPUP CLOSED WITHOUT CAMPAIGN OPEN / QUALIFYING INTERACTION
→
NOTIFICATION CENTER STATE = UNREAD
```

هذا يمنع أن تتحول مجرد عملية إغلاق النافذة إلى إشارة كاذبة بأن المستخدم قرأ الرسالة أو استوعبها.

```text
DISMISS POPUP != CONTENT CONSUMED
DISMISS POPUP != CAMPAIGN READ
UNREAD STATE PERSISTS UNTIL QUALIFYING READ EVENT
```

### 1.5 فتح الحملة من مركز التنبيهات يحولها إلى Read

اعتمد الـOwner أن **فتح العرض/الحملة فعليًا من مركز التنبيهات داخل Falcon هو حدث القراءة المباشر**.

بمجرد أن يفتح المستخدم عنصر الحملة من مركز التنبيهات ويُعرض له محتواه، تتحول حالته من `Unread` إلى `Read` بدون الحاجة إلى زر إضافي من نوع `Mark as read`.

```text
NOTIFICATION CENTER ITEM = UNREAD
        ↓
USER OPENS CAMPAIGN
        ↓
CAMPAIGN CONTENT IS DISPLAYED
        ↓
NOTIFICATION STATE = READ
```

وتبقى التفرقة التالية إلزامية:

```text
POPUP DISMISS != READ
NOTIFICATION CENTER OPEN = READ
READ != ACCEPTED OFFER
READ != SUBSCRIBED
READ != PURCHASED
READ != CAMPAIGN CONVERSION
```

حالة `Read` تعني فقط أن المستخدم فتح الرسالة/الحملة من مركز التنبيهات وعُرض له محتواها، ولا تعني أنه وافق على العرض أو اشترك أو اشترى أو نفذ أي CTA داخل الحملة.

### 1.6 بقاء الحملة في مركز التنبيهات بعد القراءة

اعتمد الـOwner أن انتقال الحملة إلى حالة `Read` **لا يزيلها من مركز التنبيهات ولا ينقلها تلقائيًا إلى الأرشيف**.

تظل الحملة موجودة في قائمة التنبيهات حتى يقرر المستخدم بنفسه إزالتها من قائمته بالضغط على زر `X` الخاص بها.

```text
NOTIFICATION STATE = READ
!=
REMOVE FROM NOTIFICATION CENTER

READ CAMPAIGN
→
REMAINS VISIBLE IN NOTIFICATION CENTER

USER PRESSES X
→
REMOVE FROM USER'S ACTIVE NOTIFICATION LIST
```

الضغط على `X` هنا هو فعل مستخدم صريح لإزالة العنصر من قائمته الحالية، ولا يُفهم منه تلقائيًا أي معنى تجاري إضافي.

```text
X / DISMISS FROM LIST != REJECT OFFER
X / DISMISS FROM LIST != UNSUBSCRIBE FROM MARKETING
X / DISMISS FROM LIST != ACCOUNT PREFERENCE CHANGE
X / DISMISS FROM LIST != DELETE CAMPAIGN GLOBALLY
```

### 1.7 انتقال الحملة إلى الأرشيف عند الضغط على X

اعتمد الـOwner أن الضغط على `X` في مركز التنبيهات **لا يحذف الحملة نهائيًا من جهة المستخدم**، بل ينقلها من قائمة التنبيهات النشطة إلى **الأرشيف**.

يبقى المستخدم قادرًا على الرجوع إلى الحملة من الأرشيف لاحقًا ضمن حدود صلاحية المحتوى وسياسة الاحتفاظ النهائية التي ستحدد في مرحلة التصميم التفصيلي.

```text
USER PRESSES X
        ↓
REMOVE FROM ACTIVE NOTIFICATION LIST
        ↓
MOVE TO ARCHIVE
        ↓
USER MAY REOPEN FROM ARCHIVE
```

وتبقى التفرقة التالية إلزامية:

```text
X != PERMANENT DELETE
X != REJECT OFFER
X != UNSUBSCRIBE
ARCHIVE != ACTIVE NOTIFICATION
ARCHIVE != CAMPAIGN CONVERSION
```

### 1.8 الحذف النهائي من الأرشيف

اعتمد الـOwner أن المستخدم **يملك خيار حذف الحملة من الأرشيف** عندما لا يريد الاحتفاظ بها ضمن سجله الشخصي القابل للعرض.

هذا الحذف يخص نسخة/ظهور الحملة لدى المستخدم في واجهة الأرشيف، ولا يُفهم منه تلقائيًا أي معنى تجاري أو تغيّر في تفضيلات التسويق أو حذف للحملة الأصلية على مستوى الـOwner أو النظام.

```text
CAMPAIGN IN ARCHIVE
        ↓
USER CHOOSES DELETE
        ↓
REMOVE FROM USER-VISIBLE ARCHIVE
```

وتبقى الحدود التالية إلزامية:

```text
ARCHIVE DELETE != REJECT OFFER
ARCHIVE DELETE != UNSUBSCRIBE
ARCHIVE DELETE != ACCOUNT PREFERENCE CHANGE
ARCHIVE DELETE != DELETE OWNER CAMPAIGN GLOBALLY
```

الحذف النهائي من منظور المستخدم لا يحدد هنا ما إذا كانت هناك سجلات تدقيق أو احتفاظ قانوني/تشغيلي غير ظاهرة للمستخدم. أي سجل إلزامي خارج واجهة المستخدم يخضع لاحقًا للعقود والسياسات الحاكمة ولا يُستنتج من قرار UX هذا.

### 1.9 تأكيد الحذف غير القابل للاسترجاع

اعتمد الـOwner أن طلب الحذف النهائي من الأرشيف **لا ينفذ مباشرة**. قبل تنفيذ الحذف يجب أن تظهر للمستخدم خطوة تأكيد صريحة توضّح بوضوح أن العنصر المحذوف من الأرشيف **لن يكون قابلًا للاسترجاع من واجهة المستخدم بعد التأكيد**.

يجب أن تتيح خطوة التأكيد للمستخدم خيارين واضحين على الأقل: إلغاء العملية والعودة دون حذف، أو تأكيد الحذف النهائي.

```text
USER REQUESTS ARCHIVE DELETE
        ↓
FINAL DELETE CONFIRMATION
  - CLEAR WARNING
  - DELETED ITEM CANNOT BE RESTORED BY USER
  - CANCEL OPTION
  - EXPLICIT CONFIRM DELETE
        ↓
USER CONFIRMS
        ↓
REMOVE FROM USER-VISIBLE ARCHIVE
```

وتبقى الحدود التالية إلزامية:

```text
DELETE CLICK != DELETE COMPLETED
CANCEL -> NO DELETION
CONFIRMED ARCHIVE DELETE = IRREVERSIBLE FROM USER UX
USER-IRREVERSIBLE DELETE != DELETE OWNER CAMPAIGN GLOBALLY
USER-IRREVERSIBLE DELETE != ERASE REQUIRED AUDIT / LEGAL RECORDS
```

المقصود بعبارة «لا يمكن استرجاع المحذوف» هنا هو عدم وجود استرجاع للمستخدم من واجهة Falcon بعد تأكيد الحذف النهائي. لا تفترض هذه العبارة حذف أي سجل تدقيق أو سجل قانوني/تشغيلي قد يلزم الاحتفاظ به خارج واجهة المستخدم وفق السياسات والعقود الحاكمة.

### 1.10 العروض المنتهية داخل الأرشيف

اعتمد الـOwner أن انتهاء صلاحية العرض **لا يزيله تلقائيًا من الأرشيف** إذا كان موجودًا هناك ولم يحذفه المستخدم نهائيًا.

يبقى العرض قابلًا للفتح والمراجعة من الأرشيف، لكن يجب أن تكون حالته ظاهرة بوضوح على أنها `Expired` حتى لا يلتبس على المستخدم أنها ما زالت فعالة أو قابلة للاستخدام.

```text
CAMPAIGN IN ARCHIVE
        ↓
OFFER VALIDITY EXPIRES
        ↓
REMAINS IN ARCHIVE
        ↓
STATUS = EXPIRED
        ↓
USER MAY STILL OPEN / REVIEW
```

وتبقى التفرقة التالية إلزامية:

```text
EXPIRED != DELETED
EXPIRED != HIDDEN FROM ARCHIVE
EXPIRED OFFER != ACTIVE OFFER
ARCHIVE VIEW != OFFER REACTIVATION
```

إظهار العرض المنتهي في الأرشيف هو لأغراض الرجوع والمراجعة فقط. لا يعني فتحه بعد انتهاء الصلاحية إعادة تفعيله أو تمديده أو إنشاء أهلية جديدة للاستفادة منه.

### 1.11 إزالة إجراء الاستفادة من العرض المنتهي

اعتمد الـOwner أن العرض الذي أصبحت حالته `Expired` داخل الأرشيف **لا يعرض زر الاشتراك أو الاستفادة من العرض أو أي CTA تجاري كان مخصصًا لتنفيذ العرض أثناء صلاحيته**.

لا يبقى الزر ظاهرًا بحالة `Disabled`، بل يزال من واجهة العرض المنتهي بالكامل حتى لا يوحي بوجود مسار تنفيذ أو استفادة ما زال متاحًا.

```text
ARCHIVED OFFER STATUS = EXPIRED
        ↓
USER OPENS EXPIRED OFFER
        ↓
SHOW CONTENT FOR REVIEW
SHOW EXPIRED STATUS
REMOVE OFFER-ACTION CTA
```

وتبقى الحدود التالية إلزامية:

```text
EXPIRED OFFER -> NO ACTIVE OFFER CTA
NO CTA != HIDE OFFER CONTENT
NO CTA != DELETE ARCHIVED OFFER
REVIEW ACCESS != EXECUTION / SUBSCRIPTION PATH
```

هذا القرار يخص CTA المرتبط بالعرض المنتهي نفسه. لا يمنع وجود تنقل عام منفصل إلى صفحات الاشتراك أو الحساب في Falcon إذا كان ذلك متاحًا من أماكن أخرى وفق تصميمها الخاص.

### 1.12 ترتيب عناصر الأرشيف حسب التاريخ فقط

اعتمد الـOwner أن ترتيب عناصر الأرشيف يكون **زمنيًا فقط حسب التاريخ**، بدون إعادة تجميع أو رفع/خفض العناصر بناءً على كون العرض `Active` أو `Expired`.

يعني ذلك أن حالة العرض لا تغيّر موضعه في الأرشيف، بل تظل الحالة مجرد وسم/معلومة مرئية داخل العنصر بينما يحدد التاريخ ترتيب القائمة.

```text
ARCHIVE ORDERING BASIS = DATE ONLY
ACTIVE / EXPIRED STATUS != SORT PRIORITY
NO STATUS-BASED GROUPING
NO ACTIVE-FIRST REORDERING
```

هذا القرار يخص ترتيب القائمة فقط، ولا يغيّر قواعد انتهاء العرض أو إمكانية فتحه أو حذف CTA عند انتهاء الصلاحية.

### 1.13 البحث داخل الأرشيف باسم العرض أو الحملة

اعتمد الـOwner أن واجهة الأرشيف تتضمن **Search** يساعد المستخدم على العثور على حملة أو عرض محفوظ في أرشيفه بالبحث عن **اسم العرض أو اسم الحملة**.

البحث يرشح عناصر الأرشيف القابلة للعرض للمستخدم فقط، ولا يغيّر ترتيب الأرشيف الأساسي أو حالة العرض أو صلاحية المحتوى.

```text
ARCHIVE SEARCH INPUT
        ↓
MATCH CAMPAIGN / OFFER NAME
        ↓
SHOW MATCHING USER-ACCESSIBLE ARCHIVE ITEMS
```

وتبقى الحدود التالية إلزامية:

```text
ARCHIVE SEARCH != GLOBAL CAMPAIGN SEARCH
ARCHIVE SEARCH != RESTORE DELETED ITEM
ARCHIVE SEARCH != CHANGE ACTIVE / EXPIRED STATUS
SEARCH RESULT != OFFER REACTIVATION
```

هذا القرار يثبت البحث بالاسم كقدرة UX داخل أرشيف المستخدم فقط. تفاصيل المطابقة التقنية والفهرسة والأداء تبقى ضمن التصميم التفصيلي والتنفيذ المصرح به لاحقًا.

### 1.14 حدود المعاينة

المعاينة البصرية هي تمثيل UX لما سيظهر للمستخدم وليست إثبات نشر أو تسليم، ولا تمنح سلطة نشر بمفردها.

```text
VISUAL PREVIEW != PUBLISHED
VISUAL PREVIEW != DELIVERED
PREVIEW SHOWN != OWNER CONFIRMATION
OWNER CONFIRMATION REQUIRED
```

كما أن أي اختلافات نهائية ناتجة عن حجم الشاشة أو القناة أو القيود التشغيلية لا يتم اختراع تفاصيلها هنا، وسيتم حسمها لاحقًا ضمن التصميم التفصيلي والتنفيذ المصرح به.

هذا القرار يثبت اتجاه UX/Product فقط، ولا يحدد آلية rendering أو publishing أو exact runtime implementation.
