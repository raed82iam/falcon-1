# Shared Falcon Web - خريطة الموقع والشاشات

**Status:** `DRAFT / DISCUSSION ONLY`

الهدف من هذا الملف تحديد المساحات الرئيسية ومسار انتقال المستخدم بينها قبل تثبيت التفاصيل التقنية أو الـWireframes.

هذا الملف يصف تجربة الاستخدام المرشحة فقط، ولا يحدد آلية Authentication أو Session أو Runtime routing النهائية.

---

## 1. المساحات الرئيسية

Shared Falcon Web ينقسم مبدئيًا إلى ثلاث مساحات واضحة:

```text
PUBLIC FALCON HOME
        ↓
SIGN IN / CREATE ACCOUNT
        ↓
AUTHORITATIVE USER / ROLE RESOLUTION
        ↓
┌──────────────────────┬─────────────────────────┐
│ Regular Falcon User  │ Project Owner           │
│        ↓             │        ↓                │
│ My Applications      │ Falcon Command Center   │
└──────────────────────┴─────────────────────────┘
```

قاعدة مهمة:

`PUBLIC FALCON HOME != USER HOME != OWNER COMMAND CENTER`

## 2. Public Falcon Home

هذه هي الصفحة العامة قبل تسجيل الدخول.

الغرض منها:

- تقديم Falcon للزائر بصورة عامة وغير حساسة.
- عرض أنظمة/Applications Falcon الحالية والمستقبلية بطريقة واضحة مع تمييز الحالي عن الـFuture/Candidate.
- إعطاء مدخل واضح إلى `Sign In` و`Create Account`.
- السماح بصفحات تعريف عامة لكل Falcon System/Application عندما يكون ذلك مناسبًا.
- عدم عرض حالة تشغيل داخلية حساسة أو أوامر تحكم أو معلومات Owner خاصة.

الـHeader المرشح:

```text
FALCON | About | Applications | Sign In | Create Account
```

### 2.1 Owner clarification — Falcon OS vs FSATS hierarchy

قرار الـOwner بتاريخ 2026-08-15:

`Falcon OS` هو المظلة العامة القابلة لاحتواء أنظمة/مجالات متعددة مستقلة عن بعضها على مستوى المنتج.

`Falcon Self-Aware Trading System (FSATS)` هو نظام التداول داخل Falcon، وهو ليس مرادفًا لكل Falcon OS، وليس container لأي مجال أعمال غير التداول.

الهيكل الحالي داخل FSATS هو:

```text
Falcon Self-Aware Trading System (FSATS)
│
├── 1. Falcon Self-Aware Trading Application (FSATA)
├── 2. Falcon Self-Aware Provider Management Application (FSAPMA)
├── 3. Falcon Trading Guardian Application (FTGA)
├── 4. Falcon Self-Aware Trading Simulation Application (FSTSimA)
└── 5. Falcon Self-Aware Resource Management Application (APP-RSC)
```

أي نظام/برنامج مستقبلي غير تابع لمجال التداول، مثل Accounting أو Warehouse أو أي مجال آخر، لا يوضع تحت FSATS. يظهر بجانب FSATS تحت Falcon OS كمجال/نظام مستقل وفق معماريته وسلطته الخاصة.

النموذج الصحيح للعرض العام هو:

```text
FALCON OS
│
├── FSATS — Falcon Self-Aware Trading System
│   ├── FSATA
│   ├── FSAPMA
│   ├── FTGA
│   ├── FSTSimA
│   └── APP-RSC
│
├── FUTURE ACCOUNTING SYSTEM / APPLICATION FAMILY
├── FUTURE WAREHOUSE SYSTEM / APPLICATION FAMILY
└── OTHER FUTURE FALCON SYSTEMS / APPLICATION FAMILIES
```

القواعد الثابتة:

```text
FALCON_OS != FSATS
FSATS = TRADING DOMAIN SYSTEM
FSATS_CHILD_APPLICATION != FALCON_TOP_LEVEL_SYSTEM
NON_TRADING_DOMAIN != FSATS_CHILD
FUTURE_DOMAIN_SYSTEM -> SIBLING_OF_FSATS_UNDER_FALCON_OS
```

بالتالي، Public Falcon Home يستطيع إبراز FSATS كالنظام الحالي الرئيسي، ثم يعرض تطبيقاته الخمسة داخله بصريًا، بينما تبقى الأنظمة المستقبلية غير التداولية في مستوى موازٍ لـFSATS وليس داخله.

المحتوى العام والهوية التسويقية النهائية تبقى Candidate إلى أن تمر بمراجعاتها المناسبة.

## 3. Sign In Routing

بعد نجاح تسجيل الدخول، Shared Web لا يقرر الهوية أو الصلاحية من عنده، بل يعتمد على النتيجة authoritative من الجهة المالكة للهوية/الصلاحيات عندما يتم تعريف عقدها النهائي.

مسار UX المرشح:

```text
SIGN IN
  ↓
Identity / Role confirmed authoritatively
  ↓
Is Project Owner?
  ├─ YES → Falcon Command Center
  └─ NO  → My Applications
```

### قاعدة Owner مباشرة

إذا تم التعرف على المستخدم بصورة authoritative على أنه `Project Owner`:

**يتم توجيهه مباشرة إلى `Falcon Command Center / Owner Page`.**

لا يمر الـOwner أولًا على صفحة المستخدم العادي `My Applications`.

من داخل `Falcon Command Center` يستطيع الـOwner لاحقًا فتح Applications المسموح بها والتنقل بينها.

`WEB-DETECTED LABEL != AUTHORITATIVE OWNER IDENTITY`

الـWeb يعرض وينفذ تجربة التوجيه فقط، ولا يخترع سلطة الـOwner أو يثبت هويته بنفسه.

## 4. Create Account / Application Selection

الاتجاه الحالي:

```text
Create Falcon Account
        ↓
Choose available Falcon systems / subscriptions
        ↓
One or more top-level Falcon systems may be selected when offered
        ↓
System/Application-specific onboarding when required
        ↓
My Applications
```

في الحالة الحالية، FSATS هو Trading System، والتطبيقات الخمسة التابعة له لا تعامل تلقائيًا كخمسة اشتراكات Falcon مستقلة في Public Falcon Home لمجرد أنها Applications داخلية للنظام. أي entitlement/subscription model نهائي يبقى خاضعًا لعقوده المالكة.

مثال مستقبلي على مستوى Falcon الأعلى:

```text
Choose your Falcon systems

☑ FSATS
☐ Accounting
☐ Warehouse

[ Continue ]
```

اختيار System/Application لا يعني تلقائيًا أن كل صلاحياته أصبحت فعالة.

```text
SIGNED_IN != SUBSCRIBED
SUBSCRIBED != AUTHORIZED_FOR_ACTION
```

حسب FCR-0081، bare FSATS subscription لا يتطلب provider/broker secrets. أي credential حساس يطلب لاحقًا فقط عند تفعيل capability تحتاجه فعلًا، وتبقى secret bytes خارج reusable Web-owned state/logs.

## 5. User Home / My Applications

هذه الصفحة الرئيسية للمستخدم العادي بعد Sign In.

الغرض منها:

- عرض أنظمة/Applications المستوى الأعلى التي يشترك بها المستخدم.
- فتح أي System/Application مشترك به.
- عرض أنظمة/Applications أخرى متاحة للاشتراك عندما يكون ذلك مسموحًا.
- إدارة الاشتراكات من منظور UX.
- إظهار حالة الوصول/الاشتراك بدون اختراع business truth.

في الوضع الحالي، المستخدم الذي يملك FSATS يرى FSATS كمدخل Trading System موحد. التطبيقات `FSATA / FSAPMA / FTGA / FSTSimA / APP-RSC` تبقى مكونات Application مستقلة داخل FSATS بحسب صلاحياتها وعقودها، وليست top-level Falcon siblings.

شكل مبدئي مستقبلي:

```text
My Applications / Systems

FSATS        [ Open ] [ Open in New Tab ]
Accounting   [ Open ] [ Open in New Tab ]

Available
Warehouse    [ Learn More ] [ Subscribe ]
```

## 6. Application Navigation / App Switcher

عند فتح System/Application، يبقى هناك مدخل موحد للتنقل بين أنظمة Falcon ذات المستوى الأعلى التي يحق للمستخدم الوصول إليها.

مثال:

```text
FALCON | FSATS ▼ | ... | User
```

ومن الـApp Switcher على المستوى الأعلى:

```text
My Applications / Systems

✓ FSATS
  Accounting

Open Falcon User Home
Manage Applications
```

التنقل الداخلي بين تطبيقات FSATS الخمسة أو الأسطح التي تقدمها لا يحولها إلى top-level Falcon systems.

المستخدم يستطيع:

- الانتقال من Falcon System إلى آخر داخل نفس تجربة Falcon عندما يكون مخولًا.
- فتح System/Application في tab/window مستقل.
- تشغيل أكثر من System/Application في tabs متوازية.

لكن:

`MULTIPLE OPEN TABS != APPLICATION COUPLING`

كل request/result يجب أن يبقى مرتبطًا بالـTarget System/Application الصحيح، ولا يعتمد على مفهوم ضمني مثل "آخر Application مفتوح" كمصدر للسلطة أو routing.

## 7. Falcon Command Center / Owner Page

هذه صفحة الـProject Owner بعد Sign In، وليست الصفحة العامة وليست User Home.

الهدف الأساسي:

`STATUS → ATTENTION → ACTION`

الأقسام المرشحة:

- `Overview`
  - الحالة العامة التي يسمح بعرضها من المصادر authoritative.
  - ملخص ما يحتاج انتباه الـOwner.

- `Applications`
  - عرض Falcon Systems وApplications ككيانات مستقلة وفق التسلسل الصحيح بينها.
  - فتح أي System/Application متاح للـOwner.
  - عرض الحالات والتنبيهات authoritative بدون امتلاك business semantics.

- `Needs Your Attention`
  - قرارات أو مراجعات أو حالات تحتاج الـOwner.
  - لا يتحول التنبيه إلى موافقة تلقائية.

- `Users`
  - إدارة المستخدمين والوصول من منظور UX، ضمن العقود والصلاحيات التي ستعتمد لاحقًا.

- `Ask Falcon / Conversational Gateway`
  - مدخل اللغة الطبيعية للـOwner.
  - يحافظ على الطلب الأصلي، التفسير structured، الجهة المستهدفة، الحالة، النتائج، والـevidence.

- `Falcon Control`
  - أدوات التحكم العامة التي تكون موجودة ومصرح بها فعليًا.
  - كل Control يعرض authoritative result من مالكه الحقيقي.

- `Emergency / Degraded Control`
  - مدخل لحالات Kill/Containment/Recovery عند توفر العقود authoritative.
  - Web AI ليس شرطًا لبقاء الحد الأدنى من emergency/degraded UX إذا بقيت المصادر غير الذكية موثوقة ومتاحة.

- `Activity / Audit`
  - تاريخ الطلبات والقرارات والنتائج والأدلة التي يسمح بعرضها.

- `Settings`
  - إعدادات Shared Web وما يقع ضمن نطاقه فقط.

## 8. Application Presentation Pattern

Shared Web هو Shared Falcon Application مستقل، ولا يصبح مالكًا لمعنى Applications الأخرى.

النمط العام المرشح لأي System/Application:

`Identity + Parent/Domain Relationship + Access/Subscription State + Status + Alerts + User/Owner-facing summary + UI contribution + governed requests/commands when they actually exist`

Application failure أو removal أو replacement يجب ألا يحول الويب إلى مالك business truth بديل.

## 9. حالات يجب أن تظهر بوضوح

الواجهة يجب أن تفرق بصريًا بين الحالات authoritative أو المعاني المكافئة التي تأتي من أصحابها، مثل:

- `OWNER_ACCEPTED`
- `ACTIVE DESIGN`
- `NOT AUTHORIZED`
- `HEALTHY`
- `DEGRADED`
- `UNKNOWN`
- `AWAITING OWNER`
- `CONTAINED`
- `STATE_STALE`
- `SOURCE_UNTRUSTED`
- `CONTROL_PATH_UNAVAILABLE`

الأسماء النهائية للـenums لا يملكها Web إذا كانت صادرة عن Foundation/Application contracts.

قواعد ثابتة:

```text
PASS != OWNER_ACCEPTED
ROUTE_EXISTENCE != AUTHORITY
DELIVERY != ACCEPTANCE
REQUEST_SENT != ACTION_ACCEPTED != ACTION_COMPLETED
RESTARTED != RECOVERED
REPAIRED != TRUSTED
TESTED != RELEASED
```

## 10. التصميم البصري

الاتجاه الحالي Candidate:

- Graphite / Charcoal.
- هادئ وواضح.
- ألوان قوية فقط للحالات والتنبيهات المهمة.
- Public Home لا يبدو Trading Dashboard.
- Public Home يستطيع إبراز FSATS كـTrading System رئيسي حاليًا مع تطبيقاته الخمسة تحته، بدون تقديمها كخمسة Falcon top-level systems.
- User Home يركز على Falcon Systems/Applications والوصول.
- Owner Command Center يركز على الحالة والانتباه والقرار.
- الشكل النهائي يأتي بعد تثبيت الوظائف والـWireframes.

## 11. حدود غير محسومة بعد

هذه الخريطة لا تحسم بعد:

- Authentication implementation.
- Session/SSO implementation.
- Role/identity authoritative source technical realization.
- exact System/Application subscription/entitlement contracts.
- final request/response schemas.
- exact credential storage/transfer mechanism.
- runtime routes.
- deployment/hosting.
- emergency enforcement implementation.

هذه التفاصيل تمر من أصحابها وعقودها ومراجعاتها قبل أي implementation-ready freeze.
