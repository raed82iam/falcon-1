# Shared Falcon Web - محادثة المستخدم مع AI

**Status:** `DRAFT / DISCUSSION ONLY`

هذا الملف يسجل اتجاه تجربة المستخدم العادي داخل FSATS فيما يتعلق بالمحادثة مع الذكاء الاصطناعي لعرض الاستشارات والتحليل والشرح بصورة سلسة وقابلة للفهم.

هذا تخطيط UX/Product فقط. لا يحدد من هو الـAI runtime principal النهائي، ولا يثبت model/provider، ولا يمنح execution/implementation/runtime authority.

---

## 1. قاعدة أساسية

كل مستخدم FSATS يجب أن يملك واجهة محادثة مع AI داخل تجربة التطبيق.

الغرض الأساسي من هذه المحادثة هو جعل مخرجات FSATS قابلة للفهم والاستخدام، بدل إجبار المستخدم على قراءة تقارير أو أرقام خام فقط.

```text
FSATS USER
   ↓
AI CHAT
   ↓
Consultation / Analysis / Explanation / Recommendation Presentation
```

---

## 2. ما الذي يقدمه الـAI Chat للمستخدم

الوظائف المرشحة من منظور Web/UX تشمل:

- عرض الاستشارة للمستخدم بلغة طبيعية.
- شرح التحليل بطريقة قابلة للفهم.
- تبسيط النتائج المعقدة بدون تغيير معناها.
- الإجابة عن أسئلة المستخدم حول التحليل أو النتيجة المعروضة.
- شرح أسباب التوصية، العوامل المهمة، المخاطر، وعدم اليقين عندما تكون هذه المعلومات متاحة من أصحابها authoritative.
- السماح بالمحادثة المتتابعة بحيث يستطيع المستخدم أن يسأل أسئلة متابعة بدل بدء طلب جديد لكل تفصيل.
- عرض معلومات منظمة أو جداول/بطاقات/رسوم داخل المحادثة عندما تكون مفيدة، مع بقاء مصدر business truth في Application المالكة.

---

## 3. Novice-First Exploration

FSATS يجب أن يكون قابلًا للاستخدام حتى من شخص لا يعرف التداول أصلًا ويريد فقط الاستكشاف والتعلم وفهم ما يراه.

لا يجوز أن تفترض الواجهة أن المستخدم يعرف:

- ticker symbols.
- المؤشرات الفنية.
- أنواع الأوامر.
- المصطلحات المالية أو التداولية.
- كيفية كتابة query أو command.
- ما هي البيانات التي يحتاجها لكي يطلب تحليلًا جيدًا.

المستخدم يستطيع البدء بكلام بسيط جدًا، مثل:

```text
أنا ما بعرف بالتداول، اشرحلي من وين أبدأ.
```

أو:

```text
شو يعني سهم أصلًا؟
```

أو:

```text
بدي أستكشف شركات تقنية قوية، شو ممكن تورجيني؟
```

أو:

```text
سمعت عن Apple، احكيلي عنها بطريقة بسيطة.
```

الـAI من منظور UX يجب أن يقابل مستوى المستخدم بدل إجبار المستخدم على الصعود لمستوى تعقيد النظام.

يمكنه أن:

1. يشرح المصطلحات عند ظهورها.
2. يقترح أسئلة متابعة مفيدة بدل ترك المستخدم أمام شاشة فارغة.
3. يسأل clarification بسيط فقط عندما يحتاجه فعلًا.
4. يبدأ بإجابة سهلة ثم يسمح للمستخدم بطلب تفاصيل أعمق.
5. يميز بين التعليم العام، المعلومة، التحليل، والتوصية.
6. لا يدفع المستخدم نحو Automated Trading لمجرد أنه يستكشف أو يسأل.
7. لا يفترض وجود خبرة أو portfolio أو broker account.

المبدأ:

```text
USER TRADING KNOWLEDGE MAY BE ZERO
```

لكن هذا لا يعني تبسيط الحقيقة لدرجة تشويهها.

```text
SIMPLIFY PRESENTATION
!=
SIMPLIFY AWAY RISK / UNCERTAINTY / LIMITATIONS
```

تجربة الاستكشاف يجب أن تسمح للمستخدم أن ينتقل تدريجيًا:

```text
CURIOUS USER
    ↓
UNDERSTANDS BASIC CONCEPTS
    ↓
EXPLORES MARKETS / ASSETS
    ↓
ASKS FOR ANALYSIS
    ↓
ASKS FOR COMPARISONS / RECOMMENDATIONS
    ↓
OPTIONALLY, LATER CHOOSES AUTOMATED TRADING
```

ولا يوجد أي افتراض أن كل مستخدم يجب أن يصل إلى Automated Trading.

---

## 4. Advisory / Non-Execution Boundary

الـAI Chat هو جزء أساسي من تجربة الاستشارة والتحليل، ولا يتطلب من المستخدم تقديم API أو broker secret لمجرد استخدامه.

```text
AI CHAT FOR CONSULTATION / ANALYSIS
!=
AUTOMATED TRADING
```

```text
CONSULTATION
ANALYSIS
RECOMMENDATIONS
EXPLANATION
FOLLOW-UP QUESTIONS
EXPLORATION / LEARNING

→ NO USER BROKER/API CREDENTIAL REQUIRED
```

User API/broker credentials تصبح ذات صلة فقط عند اختيار المستخدم بشكل منفصل تفعيل `Automated Trading` وفق onboarding/authority الخاصة بذلك المسار.

---

## 5. AI Chat لا يخلق Execution Authority

وجود AI Chat أو توصية داخل المحادثة لا يعني تنفيذ صفقة.

```text
AI RESPONSE != TRADE ORDER
RECOMMENDATION != EXECUTION AUTHORITY
USER QUESTION != AUTOMATED TRADING OPT-IN
CHAT CONFIRMATION != BROKER AUTHORIZATION
```

إذا أراد المستخدم لاحقًا الانتقال من الاستشارة إلى Automated Trading، يجب أن يكون ذلك انتقالًا واضحًا ومنفصلًا في UX، ولا يحدث ضمنيًا بسبب محادثة أو توصية.

---

## 6. تجربة المستخدم المرشحة

داخل FSATS يمكن أن يكون الـAI Chat عنصرًا دائم الوصول، مثل:

```text
FALCON | FSATS | ... | AI Chat | User
```

أو مساحة رئيسية داخل التطبيق:

```text
FSATS

Overview
Explore / Learn
Markets / Analysis
Portfolio / Relevant User Views
AI Advisor / Chat
Automated Trading
Settings
```

الأسماء والموقع النهائي Candidate إلى أن يتم تثبيت Site Map/Wireframes.

---

## 7. شكل المحادثة

مثال UX توضيحي لمستخدم جديد تمامًا:

```text
User:
أنا ما بعرف بالتداول بس بدي أستكشف.

AI:
تمام. نقدر نبدأ بدون أي افتراضات.
مثلاً أقدر أشرحلك كيف يعمل السوق، أو نختار شركة معروفة ونشوف كيف نفهم وضعها خطوة خطوة.

User:
خلينا Apple.

AI:
يعرض تعريفًا بسيطًا أولًا، ثم يطلب/يعرض بيانات وتحليل FSATS بالمستوى المناسب.

User:
طيب شو أهم خطر عليها؟

AI:
يعرض المخاطر وسببها بلغة مفهومة.
```

ومثال آخر لمستخدم أقدم:

```text
User:
شو رأيك بالسهم X اليوم؟

AI:
بناءً على التحليل المتاح من FSATS، الصورة الحالية هي...

- الاتجاه: ...
- العوامل الداعمة: ...
- المخاطر: ...
- مستوى الثقة/عدم اليقين: ...

User:
اشرحلي ليش الخطر مرتفع؟

AI:
السبب الرئيسي هو...
```

المحادثة يجب أن تكون سهلة وطبيعية، لكن لا تخفي الفرق بين fact، analysis، recommendation، uncertainty، وauthoritative state.

---

## 8. Truth and Attribution

Shared Web لا يخترع التحليل المالي أو business truth الخاص بـFSATS.

الـWeb يعرض ويقدم conversationally المعلومات التي تأتي من المالك الفعلي داخل FSATS عبر العقود المعتمدة مستقبلًا.

يجب الحفاظ على الفصل التالي:

```text
WEB PRESENTATION
!=
FSATS BUSINESS ANALYSIS OWNERSHIP
```

وعندما تكون المعلومة stale أو unknown أو غير متاحة، لا يجوز للـChat عرضها وكأنها current/certain.

---

## 9. User Chat vs Owner Conversational Gateway

محادثة المستخدم العادي تختلف عن `Owner Conversational Gateway`.

### User AI Chat

الغرض:
- الاستكشاف والتعلم.
- الاستشارة.
- التحليل.
- التفسير.
- التوصيات.
- أسئلة المتابعة.
- فهم نتائج FSATS.

### Owner Conversational Gateway

الغرض قد يشمل، ضمن authority الفعلية:
- الاستعلام الإداري/الحوكمي.
- طلب تغييرات أو قرارات.
- مراجعة الأدلة والحالات.
- Owner-governed requests/actions.

```text
USER AI CHAT != OWNER COMMAND / GOVERNANCE GATEWAY
```

حتى لو استخدم الاثنان واجهة chat متشابهة بصريًا، الصلاحيات والمعنى والعقود لا تُدمج تلقائيًا.

---

## 10. Multi-User Isolation

كل مستخدم يجب أن يرى محادثاته وسياقه المصرح له فقط.

```text
USER_A_CHAT_CONTEXT != USER_B_CHAT_CONTEXT
```

ولا يجوز استخدام محادثة مستخدم كطريق للوصول إلى بيانات أو صلاحيات مستخدم آخر أو Application أخرى.

Exact conversation-history retention, privacy, tenancy, memory, deletion, export, and audit policy remain unresolved until the owning security/data/contracts are materialized.

---

## 11. Degraded / AI-Unavailable Experience

وجود AI Chat لا يعني أن كل FSATS UX يجب أن يتوقف إذا أصبح AI غير متاح أو غير موثوق.

إذا بقيت نتائج أو views غير المعتمدة على AI موثوقة ومسموح بعرضها، يمكن للـWeb الاستمرار في عرضها مع حالة واضحة مثل AI unavailable/degraded.

```text
AI CHAT UNAVAILABLE
!=
AUTOMATIC TOTAL WEB FAILURE
```

Exact degraded behavior remains dependent on the authoritative Application/Foundation contracts.

---

## 12. ما لم يتم حسمه بعد

لا يزال مفتوحًا ويجب ألا يخترعه Shared Web:

- exact FSATS AI component/principal responsible for user advisory conversation.
- exact request/response schema and routing.
- conversation persistence/history ownership.
- retention/deletion/export/privacy policy.
- exact user context available to the AI.
- whether and how prior conversations may be reused as context.
- exact explainability/evidence attachment format.
- rate/resource limits per user.
- AI model/provider selection.
- final safety/compliance/legal presentation requirements.
- final transition UX from advisory chat to Automated Trading opt-in.
- final onboarding mechanism for detecting or asking about user experience level, if any.

---

## 13. Planning Rule

الهدف هو جعل FSATS مفهومًا حتى لمستخدم يبدأ من صفر معرفة، عبر conversation-first experience، بدون تحويل الـChat إلى authority shortcut.

```text
MAKE IT EASY TO EXPLORE
MAKE IT EASY TO UNDERSTAND
WITHOUT MAKING IT EASY TO BYPASS AUTHORITY
```

هذا الملف لا يعني `APPROVED` ولا `IMPLEMENTATION AUTHORIZED`.
