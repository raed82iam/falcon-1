# Shared Falcon Web - حفظ وتطبيق إعدادات الشارت

**Status:** `DRAFT / DISCUSSION ONLY`

هذا الملف يسجل قرارات UX/Product الخاصة بحفظ وإعادة استخدام إعدادات الشارت داخل FSATS. لا يمنح implementation/runtime/execution authority.

---

## 1. حرية التعديل

المستخدم يستطيع إضافة وإزالة مدارس Falcon واستراتيجياته والمؤشرات الفنية على الشارت بحرية ضمن ما هو متاح فعليًا لذلك السوق/الأصل وضمن entitlement الفعلي لخطة المستخدم.

```text
USER MAY ADD
USER MAY REMOVE
USER MAY COMBINE WHEN ENTITLED
```

---

## 2. الحفظ اختياري وبقرار المستخدم

عندما يبني المستخدم تركيبة شارت يريد الاحتفاظ بها، تسأله الواجهة إن كان يريد حفظها كـ `Preset / Chart Layout` حتى يستطيع إعادة استخدامها على أصول أخرى، عندما تكون خاصية الحفظ متاحة ضمن entitlement الفعلي للمستخدم.

الحفظ لا يتم افتراضيًا بدون اختيار المستخدم.

```text
EDIT = USER CONTROLLED
SAVE = USER OPT-IN WHEN ENTITLED
PRESET = REUSABLE CHART CONFIGURATION
```

الـPreset يحفظ إعدادات العرض والاختيارات فقط، ولا ينشئ استراتيجية Falcon جديدة ولا يغيّر معنى مدرسة أو استراتيجية ولا يمنح أي صلاحية تداول أو تنفيذ.

---

## 3. تطبيق Preset على أصل آخر

عند تطبيق Preset محفوظ على سهم/أصل آخر، يجب فحص قابلية تطبيق كل طبقة أو مؤشر على الأصل الجديد وفق المخرجات والقدرات authoritative التي توفرها الجهة المالكة.

إذا كانت بعض الطبقات صالحة وبعضها غير صالح/غير متاح، لا يجوز للواجهة أن تتظاهر بأن كامل الـPreset طُبّق بنجاح.

الاتجاه الحالي:

```text
APPLY PRESET
     ↓
CHECK EACH LAYER / INDICATOR
     ↓
APPLY WHAT IS VALID
     ↓
EXPLICITLY REPORT WHAT WAS NOT APPLIED
     ↓
EXPLAIN WHY WHEN AUTHORITATIVE REASON IS AVAILABLE
```

مثال UX تصوري فقط:

```text
Preset applied with exceptions

Applied:
- School A
- RSI
- Moving Average

Not applied:
- Strategy B
  Reason: not applicable / not available for this asset
```

الأسماء والرسائل النهائية ليست ثابتة بعد.

---

## 4. الشفافية جزء من ذكاء Falcon

الـOwner أو المستخدم قد يتعمد اختيار مدرسة/استراتيجية أو Preset غير مناسب لأصل معيّن لاختبار ما إذا كان Falcon يفهم حدود ما يطبقه.

لذلك يجب أن تكون الاستجابة صريحة وواضحة، لا صامتة ولا مزيفة.

```text
NOT APPLICABLE != SILENTLY APPLIED
PARTIAL APPLY != FULL SUCCESS
UNKNOWN REASON != INVENTED REASON
```

إذا لم تكن هناك علة authoritative متاحة، يجب أن تقول الواجهة إن السبب غير متاح/غير معروف بدل اختراع تفسير.

المبدأ:

```text
FALCON INTELLIGENCE INCLUDES KNOWING WHEN SOMETHING DOES NOT FIT
```

---

## 5. تسمية Presets بواسطة المستخدم

يستطيع المستخدم، عندما يكون الحفظ متاحًا ضمن خطته، حفظ أكثر من Preset وتسميتها بنفسه بأسماء تساعده على تذكر غرض كل إعداد، مثل:

```text
تحليل طويل
Gann + RSI
Scalping View
```

الاسم هو تسمية شخصية لتنظيم إعدادات المستخدم فقط، ولا يغيّر معنى المدارس أو الاستراتيجيات ولا يجعل الـPreset استراتيجية Falcon جديدة.

المستخدم يستطيع لاحقًا اختيار الـPreset بالاسم، وتعديله، ثم حفظ التعديل أو حفظ نسخة جديدة حسب ما تسمح به تجربة الاستخدام النهائية وentitlement الفعلي.

```text
PRESET NAME = USER ORGANIZATION
PRESET NAME != STRATEGY IDENTITY
PRESET NAME != TRADING AUTHORITY
```

---

## 6. اختيار Default Preset والتحكم به

عندما تكون خاصية Presets متاحة ضمن خطة المستخدم، يستطيع اختيار أي Preset محفوظ ليكون **Default Preset** للشارت.

عند وجود Default، يكون هو إعداد العرض المفضل الذي تحاول الواجهة تطبيقه تلقائيًا عند فتح سهم/أصل جديد، مع استمرار قواعد التحقق من قابلية تطبيق كل طبقة وعدم الادعاء بأن كل العناصر طُبقت إذا كان بعضها غير صالح أو غير متاح لذلك الأصل.

المستخدم يظل صاحب القرار الكامل، ويستطيع في أي وقت:

- تعيين Preset آخر كـDefault؛
- إزالة الـDefault الحالي بالكامل والعودة إلى الرسم الأساسي؛
- تغيير الـDefault لاحقًا بدون حذف Presets المحفوظة؛
- استخدام Preset مختلف مؤقتًا بدون أن يصبح Default تلقائيًا.

```text
DEFAULT PRESET = USER-SELECTED PREFERENCE
DEFAULT MAY BE CHANGED
DEFAULT MAY BE REMOVED
USING ANOTHER PRESET != CHANGE DEFAULT
DEFAULT APPLY != GUARANTEED FULL APPLICABILITY
```

الـDefault هو تفضيل عرض للمستخدم فقط، ولا يخلق تحليلًا أو استراتيجية أو قرار تداول أو صلاحية تنفيذ جديدة.

---

## 7. نطاق الـDefault يحدده المستخدم

لا نفرض من التصميم أن يكون الـDefault واحدًا لكل FSATS أو مختلفًا لكل سوق.

عند تعيين Preset كـDefault، تسأل الواجهة المستخدم عن النطاق الذي يريده، بحيث يكون الاختيار بيده. الاتجاه الحالي يدعم على الأقل المفهومين التاليين في UX planning:

```text
USE AS DEFAULT FOR ALL APPLICABLE MARKETS
OR
USE AS DEFAULT FOR THIS MARKET
```

وبذلك يمكن للمستخدم أن يختار Preset عامًا إذا كانت هذه طريقته المفضلة، أو Default خاصًا بسوق معيّن إذا كان يريد إعدادًا مختلفًا للسوق الأمريكي والكريبتو أو أي سوق آخر يضاف لاحقًا.

المستخدم يستطيع لاحقًا تغيير هذا الاختيار أو إزالة الـDefault.

```text
DEFAULT SCOPE = USER CHOICE
SYSTEM MUST NOT SILENTLY ASSUME GLOBAL OR MARKET-SPECIFIC SCOPE
```

الصياغة النهائية للخيارات وعدد مستويات النطاق ستثبت لاحقًا في مرحلة UX التفصيلية، لكن القرار الحالي هو أن **النظام يسأل المستخدم بدل فرض نطاق واحد عليه**.

---

## 8. أكثر من Layout لنفس الأصل

القدرة موجودة في اتجاه UX الحالي، عندما تكون متاحة ضمن entitlement، بحيث يمكن للمستخدم الاحتفاظ بأكثر من إعداد/عرض لنفس السهم أو الأصل، مثل Layout للتحليل الطويل وآخر للمضاربة أو منظور تحليلي مختلف.

هذا لا يغيّر قواعد تسمية Presets أو الـDefault أو صلاحية الطبقات على الأصل.

---

## 9. الإتاحة المرحلية ثم VIP

قرار الـOwner الحالي هو أن قدرات الشارت المتقدمة تكون متاحة لجميع المستخدمين خلال فترة التجربة الأولى، ثم تطبق حدود Standard/VIP بعد انتهاء تجربة الـVIP.

### 9.1 مدارس Falcon

مدارس Falcon التحليلية مميزة وخاصة بـFalcon وليست جزءًا من الأدوات العادية الشائعة التي يحصل عليها المستخدم Standard.

بعد انتهاء تجربة الـVIP:

```text
FALCON SCHOOLS = VIP ONLY
STANDARD USER = NO FALCON SCHOOL OVERLAY ACCESS
```

يمكن أن تبقى المدارس ظاهرة في الواجهة كقدرات VIP مع توضيح أنها تتطلب Upgrade، لكن لا تعتبر متاحة للتطبيق بدون entitlement authoritative.

### 9.2 الاستراتيجيات للمستخدم Standard

بعد انتهاء تجربة الـVIP، المستخدم Standard يستطيع استخدام **استراتيجية واحدة فقط في نفس الوقت وعلى أصل واحد فقط على مستوى حسابه/جلسة FSATS وفق النموذج النهائي**.

المقصود ليس استراتيجية واحدة لكل صفحة أو لكل سهم مفتوح. إذا كانت الاستراتيجية مفعلة على سهم A، لا يستطيع تفعيل استراتيجية على سهم B قبل إزالة/إيقاف الاستراتيجية النشطة على سهم A.

```text
STANDARD USER:
MAX ACTIVE STRATEGY = 1
MAX ASSETS WITH ACTIVE STRATEGY = 1

STRATEGY ACTIVE ON ASSET A
        ↓
TRY STRATEGY ON ASSET B
        ↓
BLOCK SECOND ACTIVATION
        ↓
ASK USER TO REMOVE ACTIVE STRATEGY FROM ASSET A
OR UPGRADE WHEN THE PREMIUM PATH APPLIES
```

فتح أكثر من سهم في صفحات أو مساحات مختلفة لا يضاعف هذا الحد:

```text
MORE OPEN ASSET PAGES != MORE STANDARD STRATEGY SLOTS
```

### 9.3 الاستراتيجيات والمدارس للمستخدم VIP

المستخدم VIP يستطيع، ضمن ما تسمح به Application-owned semantics والـentitlement النهائي، تركيب أكثر من مدرسة/استراتيجية في الوقت نفسه وعلى أكثر من أصل بحسب قدرات المنتج التي تعتمد لاحقًا.

الـWeb لا يحدد من عنده صلاحية استراتيجية أو مدرسة لسهم معين، ولا يخترع الحد التقني النهائي إذا كانت الجهة المالكة تفرض قيدًا آخر.

### 9.4 المؤشرات والحفظ للمستخدم Standard

بعد انتهاء تجربة VIP:

- لا تتوفر للمستخدم Standard خاصية حفظ Presets / Layouts الجديدة؛
- يستطيع استخدام المؤشرات الفنية العادية المتاحة له؛
- الحد الأقصى للمؤشرات النشطة على الشارت هو **4 مؤشرات في نفس الوقت**؛
- تبقى الخيارات والمزايا غير المتاحة ظاهرة بدل إخفائها بالكامل؛
- عند محاولة اختيار ميزة تتطلب VIP، تظهر رسالة واضحة تدعوه للترقية لتفعيلها.

مثال UX تصوري:

```text
This feature requires VIP
Upgrade to activate it
```

### 9.5 شهر VIP مجاني لكل تسجيل جديد

قرار الـOwner الحالي:

```text
NEW FSATS USER
      ↓
1 MONTH VIP TRIAL
      ↓
7 DAYS BEFORE TRIAL END
      ↓
SHOW EXPIRY WARNING + SUBSCRIBE PATH + VIP COMPARISON LINK
      ↓
TRIAL ENDS WITHOUT SUBSCRIPTION
      ↓
STANDARD ENTITLEMENT LIMITS APPLY
```

المستخدم الجديد يحصل على **شهر كامل كتجربة VIP**. قبل انتهاء الفترة بـ**7 أيام**، تظهر له رسالة واضحة بأن تجربة VIP قاربت على الانتهاء، مع إمكانية الاشتراك للمحافظة على المزايا المتقدمة.

يجب أن يتوفر من التنبيه رابط/مدخل إلى صفحة توضح بشكل مفهوم الفرق بين `VIP` و`Standard`، بدل الاكتفاء برسالة شراء مختصرة.

مثال UX تصوري فقط:

```text
Your VIP trial ends in 7 days.
Subscribe to keep your VIP features and chart tools.
[ Compare VIP vs Standard ]   [ Subscribe ]
```

الصياغة النهائية والنموذج التجاري والسعر وآلية الدفع لم تثبت بعد.

### 9.6 الاحتفاظ المؤقت بعد انتهاء VIP

إذا انتهت تجربة VIP أو اشتراك VIP ولم يجدد المستخدم، لا تُحذف Presets / Layouts المحفوظة فورًا. تُحتفظ بها وهي **مقفلة وغير قابلة للاستخدام كمزايا VIP** خلال فترة تحذير/احتفاظ مقدارها **60 يومًا**.

خلال هذه الفترة يجب أن يعرف المستخدم أن إعداداته ما زالت محفوظة مؤقتًا وأنها ستُحذف عند نهاية مهلة الـ60 يوم إذا لم يستعد VIP entitlement. إذا عاد إلى VIP قبل انتهاء المهلة، تعود له إعداداته المحفوظة وفق الـentitlement الفعلي.

```text
VIP ENDS
    ↓
SAVED PREMIUM PRESETS / LAYOUTS = LOCKED
    ↓
60-DAY RETENTION / WARNING WINDOW
    ↓
VIP RESTORED BEFORE DEADLINE = RESTORE ACCESS
NO VIP RESTORATION BY DEADLINE = DELETE RETAINED PREMIUM CONFIGURATION
```

الهدف هو إعطاء المستخدم فرصة عادلة لاستعادة عمله بدون الاحتفاظ ببيانات Premium غير المستخدمة إلى أجل غير محدد.

```text
VIP EXPIRY != IMMEDIATE DATA DELETION
60-DAY WINDOW != FEATURE ACCESS
RETENTION != ENTITLEMENT
DELETION DEADLINE MUST BE EXPLICIT
```

### 9.7 مبادئ الإتاحة

```text
INITIAL/TRIAL VIP ACCESS != PERMANENT VIP ENTITLEMENT
VISIBLE OPTION != ENTITLED FEATURE
LOCKED FEATURE = VISIBLE WITH CLEAR UPGRADE PATH
UPGRADE PROMPT != AUTOMATIC UPGRADE
VIP BADGE != ENTITLEMENT
AUTHORITATIVE ENTITLEMENT RESULT = ACCESS BASIS
```

لا يجوز أن تتحول تجربة الشهر المجاني أو وجود زر/Badge إلى authority محلية في الـWeb. بداية/نهاية التجربة وحالة الاشتراك والـentitlement يجب أن تأتي من المصدر authoritative الذي سيُعتمد لاحقًا.

سياسة الاحتفاظ بالمحتوى Premium بعد انتهاء VIP أصبحت حاليًا **60 يومًا كفترة تحذير/احتفاظ قبل الحذف**، مع بقاء exact storage/deletion implementation آلية تقنية تُثبت لاحقًا.

---

## 10. Truth Boundary

الـWeb يملك تجربة الحفظ، الاختيار، العرض والتنبيه فقط.

قابلية تطبيق مدرسة أو استراتيجية أو مؤشر، ومعنى عدم صلاحيتها لأصل معيّن، لا يحدده الـWeb من عنده عندما يكون هذا المعنى Application-owned.

```text
WEB PRESET = PRESENTATION / USER CONFIGURATION
WEB PRESET != STRATEGY AUTHORITY
WEB PRESET != ANALYTICAL TRUTH OWNER

APPLICATION RESULT = SOURCE OF DOMAIN APPLICABILITY
```

هذا الملف لا يعني `APPROVED` ولا `IMPLEMENTATION AUTHORIZED`.
