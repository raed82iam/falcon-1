# Shared Falcon Web - إعدادات الإشعارات العامة

**Status:** `DRAFT / DISCUSSION ONLY`

هذا الملف يسجل اتجاه UX/Product الخاص بإدارة إعدادات الإشعارات على مستوى حساب Falcon العام. لا يمنح implementation/runtime/messaging authority.

---

## 1. القرار الحالي

إعدادات الإشعارات العامة تكون داخل **Falcon Account / الحساب العام**، وليس مطلوبًا من المستخدم الدخول إلى كل Application بشكل منفصل فقط حتى يتحكم بإشعاراته.

المستخدم يملك نقطة مركزية واحدة لإدارة تفضيلات الإشعارات عبر Falcon Applications المختلفة.

```text
FALCON ACCOUNT
    ↓
NOTIFICATION SETTINGS
    ↓
PER-APPLICATION PREFERENCES
```

المبدأ:

```text
ONE FALCON ACCOUNT
+
CENTRAL NOTIFICATION SETTINGS
+
APPLICATION-SPECIFIC USER CHOICE
```

---

## 2. التحكم حسب Application

من داخل إعدادات الحساب العامة، يستطيع المستخدم التحكم بإشعارات كل Application بصورة مستقلة.

مثال UX تصوري فقط:

```text
Email Notifications

FSATS          [ ON ]
Accounting     [ OFF ]
Application C  [ ON ]
```

إيقاف إشعارات Application واحد لا يعني إيقاف إشعارات باقي Applications.

```text
DISABLE FSATS EMAIL
!=
DISABLE ALL FALCON EMAIL
```

وبالمقابل، تفعيل البريد لتطبيق معين لا يعني موافقة تلقائية على كل أنواع الرسائل من كل التطبيقات.

---

## 3. خيارات الإشعارات تتبع ما هو متاح فعليًا للمستخدم

قرار الـOwner الحالي هو أن إعدادات الإشعارات داخل كل Application لا تكون مجرد مفتاح عام واحد فقط. المستخدم يستطيع التحكم في فئات الإشعارات المرتبطة بالقدرات والخيارات المتاحة له فعليًا داخل ذلك Application.

بمعنى آخر، ما يظهر له من خيارات إشعارات يجب أن ينسجم مع صلاحياته/اشتراكه/entitlement الحالي، سواء كان المستخدم `Standard` أو `VIP` أو أي مستوى آخر يعتمد مستقبلًا.

```text
USER ENTITLEMENT / AVAILABLE CAPABILITIES
                ↓
AVAILABLE NOTIFICATION CATEGORIES
                ↓
USER CHOOSES WHAT TO ENABLE / DISABLE
```

إذا كانت قدرة معينة متاحة للمستخدم، يمكن أن يكون لها خيار إشعارات خاص بها عندما تكون تلك القدرة من النوع الذي ينتج تنبيهات أو إشعارات مفيدة.

أما القدرات غير المتاحة للمستخدم بسبب خطته أو entitlement الحالي، فلا يجوز التعامل مع إشعاراتها كأنها قدرة مفعلة لديه.

```text
AVAILABLE FEATURE != NOTIFICATION FORCED ON
NOTIFICATION OPTION != FEATURE ENTITLEMENT
VIP NOTIFICATION OPTION != VIP ACCESS GRANTED
STANDARD ENTITLEMENT != VIP NOTIFICATION AUTHORITY
```

الـApplication المالك يبقى المصدر authoritative لما هي القدرات/الأحداث التي تدعم إشعارات ومعناها. Shared Web ينظم ويعرض تفضيلات المستخدم ولا يخترع أحداث Application أو صلاحياته.

## 4. نموذج إشعارات VIP وStandard

قرار الـOwner الحالي هو أن إشعارات `VIP` ليست مجموعة منفصلة بدل إشعارات `Standard`، بل هي **إشعارات Standard + إشعارات القدرات الإضافية المتاحة للـVIP**.

```text
VIP NOTIFICATIONS
=
STANDARD NOTIFICATIONS
+
VIP-ONLY NOTIFICATION CATEGORIES
```

عند انتقال المستخدم من `VIP` إلى `Standard`:

- تبقى إعدادات إشعارات Standard الفعالة خاضعة لاختيارات المستخدم العادية؛
- تتوقف فئات إشعارات VIP غير المتاحة حاليًا عن العمل لأنها لم تعد ضمن entitlement الحالي؛
- تفضيلات/إعدادات إشعارات VIP السابقة لا تُحذف فورًا؛
- تُحفظ مؤقتًا لمدة **60 يومًا** ضمن نفس سياسة الاحتفاظ المتفق عليها للبيانات Premium المؤهلة؛
- إذا عاد المستخدم إلى VIP خلال الـ60 يوم، تستعاد إعدادات إشعارات VIP المحفوظة كما كانت، مع بقاء حقه في تعديلها؛
- إذا لم يعد إلى VIP قبل نهاية الـ60 يوم، تُحذف إعدادات إشعارات VIP المحفوظة المؤهلة للحذف.

قرار الـOwner يوضح أن الرجوع إلى `VIP` داخل نافذة الـ60 يوم هو **استعادة للحالة المحفوظة كما كانت**، وليس إنشاء VIP جديد ولا إعادة تهيئة للإعدادات.

لا تظهر مطالبة لإعادة تأكيد تفضيلات VIP المحفوظة كشرط للاستعادة، ولا يتم فرض Defaults جديدة عليها. كل تفضيل مؤهل للاحتفاظ يعود إلى آخر حالة محفوظة له، بما في ذلك فئات VIP-only التي كانت `ON` أو `OFF` حسب اختيار المستخدم قبل النزول إلى Standard.

```text
VIP RETURN WITHIN 60 DAYS
      ↓
RESTORE ELIGIBLE SAVED VIP STATE AS-IS
      ↓
RESTORE LAST VIP NOTIFICATION CHOICES
      ↓
NO RESET
NO NEW DEFAULT
NO RE-CONFIRMATION REQUIRED FOR RESTORATION
```

هذه القاعدة تخص الاستعادة داخل نافذة الاحتفاظ فقط، وتبقى أي موافقة خارجية مستقلة بطبيعتها، مثل موافقة قناة البريد إذا كانت مطلوبة أصلًا.

```text
RESTORED VIP PREFERENCE
!=
NEW EXTERNAL-CHANNEL CONSENT
```

```text
VIP → STANDARD
      ↓
STANDARD NOTIFICATIONS CONTINUE PER USER CHOICE
      ↓
VIP NOTIFICATION PREFERENCES LOCKED / INACTIVE
      ↓
60-DAY RETENTION
      ↓
VIP RESTORED IN TIME → RESTORE SAVED VIP PREFERENCES
OR
DEADLINE PASSES → DELETE SAVED VIP PREFERENCES
```

إذا عاد المستخدم إلى VIP **بعد** حذف الإعدادات القديمة، يبدأ إعداد إشعارات VIP من جديد كحالة جديدة، ولا يدّعي النظام استعادة تفضيلات تم حذفها.

```text
DELETED VIP NOTIFICATION PREFERENCES
!=
RECOVERABLE OLD STATE

LATE VIP RETURN
→
NEW VIP NOTIFICATION SETUP
```

وتطبق على هذه الفترة نفس تذكيرات الاحتفاظ المعتمدة: `30 يوم متبقي` ثم `7 أيام` ثم `يوم واحد` قبل الحذف، مع احترام اختيار المستخدم لقنوات الإشعار.

## 5. Default أثناء تجربة VIP الأولى

قرار الـOwner الحالي هو أن فئات الإشعارات المتاحة أثناء **شهر VIP المجاني الأول** تكون **مفعلة افتراضيًا داخل تجربة Falcon** حتى يحصل المستخدم على التجربة الكاملة، ثم يستطيع هو إيقاف أي فئة لا يريدها لاحقًا من إعدادات الحساب العامة.

```text
VIP TRIAL STARTS
      ↓
AVAILABLE IN-FALCON NOTIFICATIONS = ON BY DEFAULT
      ↓
USER MAY TURN THEM OFF
```

هذا القرار لا يلغي حدود القنوات الخارجية. خصوصًا البريد الإلكتروني يبقى خاضعًا لموافقة المستخدم/تفعيل قناة البريد حسب القرار السابق؛ لا يجوز تفسير `ON BY DEFAULT` على أنه موافقة تلقائية على إرسال البريد إذا لم يكن المستخدم قد فعّل إشعارات البريد.

```text
IN-FALCON DEFAULT ON
!=
EMAIL CONSENT
```

### 5.1 انتهاء VIP Trial والعودة إلى Standard

قرار الـOwner الحالي هو أنه عند انتهاء شهر الـVIP المجاني وتحول المستخدم إلى `Standard`، لا يتم عمل Reset لاختيارات إشعارات Standard ولا فرض Default جديد عليها.

كل فئة Standard تحتفظ بآخر اختيار فعلي قام به المستخدم لها أثناء فترة الـVIP Trial.

```text
VIP TRIAL ENDS
      ↓
USER BECOMES STANDARD
      ↓
STANDARD NOTIFICATION PREFERENCES = PRESERVE LAST USER CHOICES
      ↓
NO STANDARD RESET
NO NEW DEFAULT OVERRIDE
```

فئات VIP-only تصبح غير فعالة لأنها لم تعد ضمن entitlement الحالي وتخضع لسياسة الاحتفاظ المؤقت المذكورة أعلاه، بينما فئات Standard تستمر بنفس حالة `ON/OFF` التي اختارها المستخدم قبل انتهاء الـTrial.

```text
STANDARD USER CHOICE SURVIVES DOWNGRADE
VIP-ONLY ENTITLEMENT LOSS != STANDARD PREFERENCE RESET
```

## 6. مثال FSATS VIP / Retention

بالنسبة لتذكيرات VIP والاحتفاظ المؤقت في FSATS:

- إذا كان المستخدم قد فعّل إشعارات البريد الخاصة بـFSATS/الفئة ذات الصلة من إعدادات Falcon العامة، يمكن إرسال التنبيهات عبر البريد وفق القرار الحالي.
- إذا أوقفها، لا تُرسل هذه التذكيرات عبر البريد.
- التنبيهات داخل Falcon لا تعني موافقة على البريد.

```text
FSATS EMAIL ENABLED → EMAIL REMINDERS MAY BE SENT
FSATS EMAIL DISABLED → NO FSATS VIP/RETENTION EMAIL
```

التذكيرات داخل التطبيق وقواعد الـ60 يوم تبقى منفصلة عن موافقة البريد.

---

## 7. سيطرة المستخدم

المستخدم يستطيع تغيير تفضيلاته لاحقًا من الحساب العام.

```text
USER MAY ENABLE
USER MAY DISABLE
USER MAY CHANGE PER APPLICATION
USER MAY CHANGE PER AVAILABLE NOTIFICATION CATEGORY
```

الهدف أن تكون إدارة الإشعارات سهلة ومركزية، بدون سلب استقلالية كل Application وبدون إجبار المستخدم على استقبال رسائل لا يريدها.

---

## 8. Boundaries

هذا القرار يخص UX/Product preference management فقط.

لا يحدد هذا الملف:

- مزود البريد النهائي؛
- آلية إرسال الرسائل؛
- العقود أو routes؛
- retention implementation؛
- الرسائل القانونية/الأمنية/التشغيلية التي قد تكون لها متطلبات مختلفة مستقبلًا.

```text
NOTIFICATION PREFERENCE != DELIVERY AUTHORITY
EMAIL ADDRESS != NOTIFICATION CONSENT
PER-APP SETTING != CROSS-APP AUTHORITY
NOTIFICATION OPTION != APPLICATION CAPABILITY AUTHORITY
```
