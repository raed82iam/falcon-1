# Shared Falcon Web - عرض تحليل الأصل وحالات الاستثناء

**Status:** `DRAFT / DISCUSSION ONLY`

هذا الملف يسجل قرار الـOwner الخاص بعرض نتائج تحليل الأصل داخل FSATS من منظور Shared Web فقط. لا يمنح implementation/runtime/trading authority ولا يغير منطق التحليل داخل FSATS.

---

## 1. الحالة الطبيعية للعرض

قرار الـOwner:

عند نجاح Falcon/Trading في إنتاج تحليل كامل للأصل، لا تعرض Shared Web قسمًا دائمًا بعنوان `Limitations` أو `What Falcon Could Not Establish` يوحي بأن Falcon ناقص أو أن التحليل بطبيعته غير مكتمل.

الحالة الطبيعية هي عرض نتيجة Falcon كما أعادها الـApplication، بصورة مباشرة وواثقة ومفهومة للمستخدم.

```text
COMPLETED ANALYSIS -> DISPLAY ANALYSIS NORMALLY
COMPLETED ANALYSIS -> NO DEFAULT LIMITATIONS PANEL
WEB MUST NOT INVENT MISSING ANALYSIS
WEB MUST NOT IMPLY FALCON INCOMPLETENESS WITHOUT APPLICATION EVIDENCE
```

---

## 2. حالات الاستثناء فقط

العقود الحالية تسمح للـApplication بإرجاع حالات خدمة/حقيقة استثنائية مثل:

- `PARTIAL`
- `UNAVAILABLE`
- `UNSUPPORTED`
- `NEEDS_CLARIFICATION`
- `REJECTED`

وعند وجود حالة فعلية من هذا النوع، أو truth/freshness limitation authoritative صادرة من الـApplication، يجب على Web إظهارها بوضوح للمستخدم لأنها حقيقة تشغيلية في تلك اللحظة وليست افتراضًا مسبقًا عن قدرة Falcon.

```text
APPLICATION_REPORTED_EXCEPTION -> WEB SURFACES IT HONESTLY
NO APPLICATION_REPORTED_EXCEPTION -> NO LIMITATION WARNING
PARTIAL != NORMAL_DEFAULT_STATE
UNAVAILABLE != FALCON_GENERAL_CAPABILITY_JUDGMENT
```

الـWeb لا يقرر أن تحليلًا ناقص، ولا يحدد سبب النقص، ولا يستنتج limitation من نفسه.

---

## 3. مدارس Falcon والاستراتيجيات

نفس القاعدة تنطبق على مدارس Falcon والاستراتيجيات:

- إذا أعاد Trading projection/analysis صالحًا وكاملًا، يعرضه Web بدون رسالة نقص إضافية.
- إذا أعاد Trading حالة `NOT_APPLICABLE`, `PARTIAL`, `UNAVAILABLE`, `UNKNOWN`, `NEEDS_CLARIFICATION`, أو حالة مماثلة authoritative، يعرض Web الحالة والسبب المتاح فقط.
- عدم انطباق Strategy على أصل محدد لا يعني أن Falcon نفسه ناقص.

```text
STRATEGY_NOT_APPLICABLE_TO_ASSET != FALCON_MISSING_CAPABILITY
SCHOOL_NOT_APPLICABLE_TO_ASSET != FALCON_MISSING_CAPABILITY
APPLICATION_EXCEPTION_STATE != WEB_INVENTED_LIMITATION
```

---

## 4. مستويان لعرض تحليل الأصل

قرار الـOwner الحالي يفصل بين عرض الصفحة المباشر وبين الشرح داخل محادثة AI.

### 4.1 العرض المباشر تحت السهم / الشارت

العرض الافتراضي تحت الأصل يكون **خلاصة فقط** وليس التقرير التحليلي الكامل.

الهدف أن يستطيع المستخدم فهم الصورة الحالية بسرعة بدون إغراق صفحة الأصل بتفاصيل كل مدرسة وكل استراتيجية.

```text
ASSET PAGE
-> FALCON SUMMARY
-> SHORT / DIRECT / CURRENT
-> NO FORCED FULL ANALYSIS DUMP
```

الخلاصة يجب أن تكون faithful للمخرجات authoritative من Trading/Application ولا يضيف Web تحليلًا من نفسه.

### 4.2 التحليل التفصيلي داخل AI Chat

عندما يسأل المستخدم AI عن الأصل أو يطلب تفسيرًا موسعًا، تكون المحادثة هي مساحة الشرح التفصيلي والعميق.

الاتجاه المطلوب للـUX هو أن يستطيع AI، اعتمادًا على المخرجات والقدرات authoritative التي توفرها FSATS، أن يشرح قدر الإمكان من الزوايا ذات الصلة، بما يشمل عندما تكون متاحة:

- نظرة قصيرة ومتوسطة وطويلة المدى.
- أكثر من Strategy مناسبة للأصل، مع شرح ما تقوله كل واحدة.
- أكثر من Falcon School مناسبة للأصل، مع شرح منظور كل مدرسة.
- أين تتفق الاستراتيجيات/المدارس وأين تختلف.
- المستويات أو المناطق أو الأهداف المهمة التي أعادها التحليل.
- لماذا تنطبق Strategy/School على هذا الأصل، أو لماذا لا تنطبق عندما تكون حالة عدم الانطباق authoritative.
- synthesis نهائي يربط نتائج التحليل معًا بدل عرض أجزاء منفصلة فقط.

مثال تصوري على مستوى UX فقط:

```text
USER: حلل لي هذا السهم بالتفصيل

AI:
- النظرة العامة: ...
- على المدى القصير: ...
- على المدى المتوسط: ...
- على المدى الطويل: ...

Strategy A:
- تنطبق على هذا الأصل لأن ...
- النتيجة الحالية ...
- المستويات المهمة ...

Strategy B:
- النتيجة الحالية ...
- تختلف عن Strategy A في ...

Falcon School X:
- منظور المدرسة ...
- ما الذي تدعمه في هذا الأصل ...

Synthesis:
- بناءً على النتائج المتاحة من FSATS، الصورة المجمعة هي ...
```

هذا المثال يوضح شكل العرض فقط ولا يخلق Strategy result أو price target أو School conclusion من Web.

```text
PAGE = SUMMARY
AI CHAT = DEEP EXPLANATION / MULTI-STRATEGY / MULTI-SCHOOL SYNTHESIS WHEN AUTHORITATIVELY AVAILABLE
```

---

## 5. حد الملكية في التحليل التفصيلي

الـAI Chat لا يعطي Web صلاحية اختراع التحليل أو إعادة بناء منطق Strategy/School.

```text
TRADING/APPLICATION = ANALYSIS TRUTH OWNER
SHARED WEB = PRESENTATION / CONVERSATIONAL UX OWNER
AI EXPLANATION != WEB-OWNED TRADING ANALYSIS
WEB SYNTHESIS PRESENTATION != STRATEGY EXECUTION LOGIC
```

إذا كانت الإجابة التفصيلية تحتاج مخرجات متعددة من Strategies/Schools أو customer-facing synthesis غير متاحة بعد عبر العقود الحالية، يجب طلبها من Application عبر FCR بدل أن يحسبها Web أو يستنتجها بنفسه.

---

## 6. حد الملكية العام

```text
TRADING/APPLICATION = ANALYSIS TRUTH OWNER
SHARED WEB = PRESENTATION OWNER
WEB PRESENTATION != ANALYSIS AUTHORITY
```

هذه المرحلة Planning/Discussion فقط.
