### What exists now

- `CON-008 v1.1` defines attributable evidence/provenance/lineage and requires evidence to remain distinct from authority, validity, completeness, acceptance and Activation.
- Current `Foundation.Authority` provides a default-deny authorization engine. Current `Foundation.Admission` governs Application/plugin admission; it is **not** an Owner-command authenticator or generic browser/Web command-admission runtime.

Therefore Web SHALL NOT substitute `Foundation.Authority` for authentication, SHALL NOT treat Application admission as command admission, and SHALL NOT invent or duplicate passphrase/PIN/session-window/high-consequence step-up truth. Until the residual generic capability is governed and implemented, any authority-bearing conversational command path remains planning-only/fail-closed.

A prior stage does not imply a later one.

Foundation remains opaque to domain payload meaning while governing generic identity/security/admission/authority/transport/evidence semantics.

- Owner authentication/session bootstrap and high-consequence step-up runtime suitable for Shared Web: **PARTIAL / residual capability requires governed planning**.
- Generic Web/browser inbound command-admission runtime: **PARTIAL / residual capability requires governed planning**.
